# omlx-top v0.1.0

A read-only terminal monitor for [oMLX](https://github.com/jundot/omlx) on macOS.
It shows what the oMLX server reports about itself over HTTP next to what the
operating system reports about the same processes, the GPU and unified memory.

First public release. The tool is read-only: it never loads, unloads, restarts
or configures anything.

## Highlights

- **TUI, one-shot and JSON.** A dashboard at 2 s, `--once` for a quick look,
  `--json` for statuslines and scripts, `--list` for deployment discovery.
- **Deployment-agnostic.** Recognises the app bundle, the Homebrew launchd
  service (`brew services start omlx`) and a manual `omlx serve`, and finds the
  real port from the listening socket instead of trusting `settings.json`.
  Several instances can run at once; `i` cycles the target.
- **Honest numbers.** Per-process CPU from `rusage` deltas, memory from
  `ri_phys_footprint`, the Activity Monitor memory model for the system, and a
  pressure row that keeps the kernel level and the derived ratio separate.
- **Pressure alert.** Kernel level 4 turns the pressure row red and bold and
  adds `⚠ PRESSURE CRITICAL` to the header. No blinking, no animation.
- **Cheap.** 0.06–0.14 % of one core and 8.0–8.8 MB RSS at the default 2 s
  interval, measured over two five-minute runs.

## Install

```sh
tar -xzf omlx-top-v0.1.0-aarch64-apple-darwin.tar.gz
install -m 755 omlx-top ~/.local/bin/   # or anywhere on PATH
omlx-top
```

Requirements: macOS 13 or later, Apple Silicon. The Mach-O deployment target is
11.0, but only macOS 26.5 (M1 Max, 32 GB) with oMLX 0.7.3 was tested.

## Usage

```sh
omlx-top                 # TUI
omlx-top --once          # one snapshot as text
omlx-top --json          # one snapshot as JSON
omlx-top --list          # discovered instances
omlx-top --interval 500ms
```

Keys: `q` quit, `space` pause, `+`/`-` interval, `a` all models, `i` cycle
instance, `m` refresh models, `r` rediscover, `?` help.

## Known limitations

- **The GPU figure is whole-device.** `Device Utilization %` comes from the AGX
  driver and includes WindowServer and every other process. There is no
  per-process GPU usage without `powermetrics` and root, so the UI labels it
  `GPU DEVICE` rather than attributing it to oMLX.
- **Polling perturbs the measurement.** Each `/api/status` call costs about 3 ms
  of CPU inside the server process, roughly 0.15 % of a core at 2 s. Documented,
  not subtracted.
- **Loopback plain HTTP only.** The HTTP client is built without TLS.
- **No persistence, energy metrics or model control.** History is a 120-sample
  in-memory ring.
